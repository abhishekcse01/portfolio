KV caching: stop recomputing the past

      
During autoregressive decoding, each new token attends to the keys and values of every earlier token. Without a cache they are recomputed at every step (quadratic total work). With a cache, only the new token's K and V are computed and appended.

      

      

    

    

      
Without cache recompute K,V for all tokens
K/V computations0

      
With KV cache compute only the new token
K/V computations0

    

    
 computed this step  read from cache  not yet generated

    
Trade-off: the cache grows linearly with sequence length × layers × heads × head-dim, so long contexts become memory-bound. That is why techniques like multi-query / grouped-query attention, paged KV memory (vLLM-style), quantised caches and sliding windows matter in serving.
    

      Illustrative 7B-class model (32 layers, 32 KV heads, head-dim 128, fp16) → full MHA KV cache ≈ 0 · with GQA (8 KV heads) ≈ 0 per sequence

  


  
  

    

      
Self-attention: who looks at whom

      
Each token forms a query that is compared against every key; a softmax turns the scores into weights over values. Hover or tap a token to see its attention row. Lower the temperature to sharpen the distribution, raise it to flatten.

      

      

    

    

    

    
Weights here are hand-designed scores for illustration (not output of a trained model). The mechanics are real: softmax(QKᵀ/√d)·V, with a causal mask when decoding so a token cannot see the future. Multi-head attention runs several of these in parallel with different learned projections.
